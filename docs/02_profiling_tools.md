# Profiling Tools

## Concept Primer

This document records the external profiling tools used in this repository. It complements `docs/00_setup.md` and `docs/01_tools.md` by focusing on system-level tracing, power observation, and ONNX Runtime profiling rather than environment capture.

For Ryzen AI workflows in this repository, no single tool provides complete attribution across CPU, iGPU, and NPU. The practical approach is to combine tools:

- `xrt-smi` for NPU state and validation
- Windows Performance Toolkit (`WPR` / `WPA`) for ETW traces
- AMD uProf for CPU and package-side counters
- HWiNFO64 for supplemental sensor logging when platform firmware exposes additional telemetry
- ONNX Runtime profiling for operator-level execution traces

## 1. AMD uProf

Homepage: https://www.amd.com/en/developer/uprof.html

AMD uProf is useful here for CPU-side and package-level monitoring. 

```powershell
AMDuProfCLI.exe timechart --list


Supported Devices:-

  Device Name          Instance
  -----------          --------
  Socket               [ 0 ]
  Core                 [ 0-15 ]
  Thread               [ 0-31 ]

Supported Counter Categories:-

 Category               Supported Device Type
 --------               ---------------------
 Power                  [ Socket, Core ]
 Frequency              [ Thread ]
 P-State                [ Thread ]
```


while`Core` and `Thread` counters are CPU views, `Socket` is a package-level view. This package-level view is not confirmed that it includes iGPU and NPU power, but it is the best available proxy for overall system power when paired with `xrt-smi` NPU state monitoring and HWiNFO64 supplemental sensor logging.


## 2. xrt-smi

Homepage: https://ryzenai.docs.amd.com/en/latest/xrt_smi.html

`xrt-smi` is the Ryzen AI NPU management and inspection utility. On Windows, Ryzen AI Software installs it under `C:\Windows\System32\AMD`, and it can be invoked directly from the configured environment.

Useful commands:

```powershell
xrt-smi examine
xrt-smi examine --report platform
xrt-smi examine --report aie-partitions
xrt-smi examine --report aie-partitions --verbose
xrt-smi validate
xrt-smi configure --pmode turbo
```

It is useful for validating NPU state, monitoring partition-level activity, and understanding the NPU esimated power.


## 3. HWiNFO64

Homepage: https://hwinfo64.com/

HWiNFO64 is a supplemental Windows sensor monitor. It is useful when the platform exposes additional telemetry such as package power, temperatures, clocks, fan speeds, or board-level sensors that are not available from `xrt-smi`.

Use it as an auxiliary data source only:

- available sensors vary by platform and firmware
- sensor names are not standardized across vendors

## 4. Windows Performance Toolkit

Official overview: https://learn.microsoft.com/en-us/windows-hardware/test/wpt/
ADK download page: https://learn.microsoft.com/en-us/windows-hardware/get-started/adk-install

Windows Performance Toolkit (WPT) includes:

- Windows Performance Recorder (`WPR`) for collecting ETW traces
- Windows Performance Analyzer (`WPA`) for analyzing `.etl` traces

I tested using WPA from above link, and it was not able to open my ETL files. WPA is now distributed via Microsoft Store, so you need to install it from there. After installing from the Microsoft Store, I was able to open the ETL files generated by WPR.

This tools is useful for coarse-grained system-level tracing, including memory utilization, CPU frequency, etc. 

### ONNX Runtime ETW Tracing with WPR

ONNX Runtime documents a WPR-based ETW workflow on Windows. Download the following profile files from the ONNX Runtime repository:

- `ort.wprp`: https://github.com/microsoft/onnxruntime/blob/main/ort.wprp
- `etw_provider.wprp`: https://github.com/microsoft/onnxruntime/blob/main/onnxruntime/test/platform/windows/logging/etw_provider.wprp

Example recording procedure:

```powershell
# Run PowerShell as Administrator

wpr -status
wpr -cancel

# CPU smoke trace
wpr -start CPU -filemode
Start-Sleep -Seconds 2
wpr -stop cpu_smoke.etl

# NPU smoke trace
wpr -start NeuralProcessing -filemode
Start-Sleep -Seconds 2
wpr -stop npu_smoke.etl

# ONNX Runtime ETW providers only
wpr -start .\ort.wprp -start .\etw_provider.wprp -filemode
Start-Sleep -Seconds 2
wpr -stop ort_only.etl -compress

# Combined trace while the workload is running
wpr -start .\ort.wprp -start .\etw_provider.wprp -start NeuralProcessing -start CPU -filemode

# Run the ONNX Runtime workload here
# python bench_ort.py --model ... --ep vitis

wpr -stop onnx_npu.etl -compress
```

Open the resulting `.etl` files in `WPA` for analysis.

## 5. ONNX Benchmark

Repository: https://github.com/amd/RyzenAI-SW/tree/main/onnx-benchmark

AMD Ryzen AI Software includes an `onnx-benchmark` utility collection. It is useful for quick benchmarks and understanding performance.

## 6. ONNX Runtime Profiler

Profiling tools documentation: https://onnxruntime.ai/docs/performance/tune-performance/profiling-tools.html

ONNX Runtime includes a built-in profiler that emits a JSON trace file. Enable it through session options:

```python
import onnxruntime as ort

sess_options = ort.SessionOptions()
sess_options.enable_profiling = True
session = ort.InferenceSession("model.onnx", sess_options=sess_options)
```

The generated profiling trace can be opened in Perfetto:

- Perfetto UI: https://ui.perfetto.dev/

This tool is useful for operator-level tracing and understanding execution timelines.
